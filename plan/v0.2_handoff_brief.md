# Ananke v0.2 讨论交接 Brief（自包含）

> 用途：把当前会话对 v0.2 计划的理解与"是否够开发"的判断打包，供切换到其他模型继续讨论。
> 读者假设：懂约束场理论 / 实验协议设计，但不一定读过本项目代码。

---

## 0. 项目身份（最重要，别跑偏）

- **Ananke 不是"更好的记忆系统"产品，而是约束场理论（Constraint Field Theory）的 AGI 架构应用实验仪器（experimental instrument）。**
- 真正的实验对象 = 理论核心命题；三层记忆架构只是让理论**可操作化、可观测、可证伪**的脚手架。
- Evidence 标准是"系统是否产生了理论预测的结构形状（possibility-space shape：分层 / 外部门控 / 单向阀）"，**不是**"记忆内容对不对"或"系统更好用了"。任何朝"优化记忆系统 / 提升回复质量"走的动作都是越界（drift）。
- 知识按可变性分层：Theory（几年）→ Protocol vN（数月）→ Implementation（数天）→ Research Log（数小时）。
- **协议（Protocol）是 Theory 与 Implementation 之间唯一合法映射层（原则 C）**。改操作定义/判定函数/证据来源 = 升协议版本（v3→v4），不得静默改冻结文件。

## 1. 理论核心命题

- 长期稳定结构依赖**不可控的外部选择压力（External Selection / 外部选择）**，而非系统内部自循环（Internal Selection / 内部选择，即 RLHF 退化原型）。
- 三层结构 = 沉淀速率分离（rate separation，原则 A）；单向阀迁移 = 慢层塑形快层、快层不回写慢层（原则 A 保护机制）。
- 反身性红线（原则 B）：系统/LLM 自生成内容、实验者近重复诱导输入 → 永不计入外部验证（External Validation, EV）。

## 2. v0.1 已冻结的事实（git tag v0.1）

- 第一道闸 working→consolidated（快→中）：代码在、真实 LLM 下触发、策略可切换。
  - persistence（External Selection）：升层 1 次（badminton, EV=2）。
  - frequency（Internal Selection）：升层 4 次（badminton + 3 条 EV=0 记忆）。
  - → Phase 3 pilot 已示分歧落在第一道闸。
- 第二道闸 consolidated→core（中→慢）：**代码在但从未真实触发，且不可策略切换**。
- 当前阈值（协议 v3 冻结）：EV/IA 互斥；EV≥0.80；IA≥0.60；dedup≥0.80；reorg≥0.90；MIGRATION_THRESHOLD=3.0；LOCAL_REORG_THRESHOLD=2；FREQUENCY_MIGRATION_THRESHOLD=3。

## 3. v0.2 的目标

让 persistence/frequency 的差异在**第二道闸（consolidated→core，最稳定层）**上可观测。因为慢层=最稳定结构，理论预测的 frequency 退化足迹本应在这里最显著，而当前这道闸既不可观测又不可切换。

路线：先解死结 → 再让第二道闸可切换 → 再用语料触发 → 再用双闸 sweep 观测分歧。

## 4. 核心障碍：结构性死结（structural deadlock）

```
REORG_SIMILARITY_THRESHOLD = 0.90  >  DEDUP_SIMILARITY_THRESHOLD = 0.80
且 pipeline 的 写入前去重（dedup）在 局部重组（reorg）之前执行
⇒ 任何 cosine≥0.90（够格触发 reorg）的候选，必然先被 dedup（≥0.80）拦下、
  永远成不了记忆、永远晋升不到中层 → reorg 触发窗口在"新写入 vs 既有记忆"路径上数学为空集
```

代码事实（已核对）：
- `pipeline.py`：dedup 在 `:36`、reorg 在 `:49`（仅对刚晋升中层的记忆调用）。
- `reorganization.py:47`：只给 `new_memory` 计 `local_reorganization_trigger`，既有中层记忆永不在跨轮累积。
- `migration.py:58` `promote_consolidated_memories()` **不接收 strategy 参数** → 两策略共用 `local_reorganization_trigger≥2`，第二道闸不可切换。

## 5. v0.2 计划（plan/v0.2_consolidated_to_core.md）的设计

- §2.1 双闸对照表：
  - External 中→慢 = `local_reorganization_trigger≥2`（结构性重组，由外部到达的新记忆驱动）。
  - Internal 中→慢 = `total_activation≥T_core`（访问计数，退化基线）。
- §2.2 代码改动：新增 `ConsolidatedPromotionStrategy` 抽象层 + `PersistenceCoreStrategy` / `FrequencyCoreStrategy` + 工厂；`promote_consolidated_memories` 加 strategy；config 加 `CONSOLIDATED_PROMOTION_STRATEGY` / `FREQUENCY_CORE_THRESHOLD`；`run_corpus.py --strategy` 联动切两道闸。
- §2.3 死结解法候选（计划**未定**，留 PI 在协议 v4 批准）：
  - **方向三（推荐）**：dedup 命中**中层**记忆 → 送 LLM 三选一 → 给既有中层记忆 +1 trigger。同时解死结 + 跨轮累积 + 语义忠实（"被持续检验的结构节点"）。
  - 方向一：DEDUP 升 0.95 / REORG 降 0.85 造窗口（改写 v0.1 记忆同一性语义 0.80）。
  - 方案 A：晋升时新记忆 C 与 A 合并/矛盾则双方各 +1（仍受死结，A 是受体语义偏移）。
  - 方向二：每轮重跑 reorg（单独用仍受死结，须配方向一）。
- §3 语料 `corpus_phase2.txt`（S1 复述累积升中层 / S3-S4 近重复重组升慢层 / S5 噪声），措辞门槛随 §2.3 方向而定。
- §4 可观测指标：升慢层数、升慢层中 `local_reorganization_trigger>0` 占比、EV>0 占比。
- §5 交付物：协议 v4 + 代码 + 语料 + 双策略真实触发 + 双闸 sweep + 测试。

## 6. "计划是否够开发"的判断（来自当前会话的助手）

**能开始搭脚手架，但核心功能差 1 个须 PI 拍板的决策 + 协议 v4 落地。**

- ✅ 充分：双闸对照设计、代码改动清单（已核对当前代码，改动点准确）、语料/对照/指标/交付物清单、现有 12 测试向后兼容（给 `promote_consolidated_memories` 加 `strategy=None` 默认解析为 PersistenceCoreStrategy 即可保住 `test_reorganization_promotes_to_core_*`）。
- ⚠️ 阻塞：
  - **Gap A（核心）**：死结解法方向未定，计划自己 deferred 到"PI 在协议 v4 批准"。方向三是推荐默认但须批准。
  - **Gap B**：`FREQUENCY_CORE_THRESHOLD` 无初始值（"待标定"）。助手提议先取 **3**（与 `FREQUENCY_MIGRATION_THRESHOLD` 同构）占位，sweep 再标定。
  - **Gap C（依赖）**：协议 v4 必须先于代码落地（原则 C）。v4 是被 Gap A 阻塞的产物。
- 🔹 助手会自行拍板（非阻塞）：frequency 模式 reorg 仍照常跑（保"唯一变量=迁移规则"）；方向三与晋升时 reorg 检查叠加；dedup→reorg 路径保留 `memory_dedup_skip` 审计 + emit `local_reorganization`（trigger_memory_id=被撞击中层记忆）。
- 🔸 理论整洁性提醒：方向三把 trigger 语义从"触发源"改写为"被持续检验的结构节点"，v4 须同步修订设计文档 §4.2"触发源"措辞。
