## 2. B1 — EV 采用 distinct-session 语义

### 裁决

一条既有记忆在后续 session 中被判定为 duplicate 时，**每个 distinct session 至多贡献一次 EV**。

- 创建该记忆的 session 不贡献 EV；
- 同一后续 session 内第一次合格 duplicate：`EV +1`；
- 同一 session 后续任何重复：继续去重，但不再增加 EV；
- 另一个后续 session 第一次合格 duplicate：可再次 `EV +1`；
- session 缺失时不得计 EV；
- 只有实际贡献 EV 后，session 才登记进“已贡献 EV 的 session 集合”。

B1 只收紧 persistence 的 EV 独立性，不把 Frequency 制度偷偷改成 distinct-session：
对非 system-guided 的后续跨 session duplicate，`total_activation` 仍按每次出现累加；同一 session
第二次及以后只增加 Frequency 使用的 total_activation，不再增加 EV。创建 session 内 duplicate
沿用既有“去重、无激活信号”规则。若未来要改变 total_activation 的来源语义，须另走 §0。

**PI 补充裁决（惰性规则）**：`system_guided=True` 的输入不计 EV，也不占用该 session 未来贡献
EV 的资格。v0.2 正式语料中该值恒为 False；此规则在 v0.2 不产生动力学效果，效力始于未来真正
启用 system-guided 来源标记时。

### 数据结构与审计要求

- 记忆持久化“已贡献 EV 的 session 集合”；
- 创建来源与当前输入来源采用双轨字段：
  - `source_session_id/source_dia_id/source_speaker`：记忆首次创建来源；
  - `input_session_id/input_dia_id/input_speaker`：本轮输入来源，仅进入事件上下文；
- speaker 与 dia_id 在 v0.2 中是惰性审计元数据，不进入计分、晋升或淘汰；
- 事件必须记录本次 EV 是否为该 session 首次贡献。

### 改变的可观测量

EV 总量预期下降；同一 session 内的重复密度不再放大 persistence，P/F 的第一道闸分歧集可能改变。

### 反驳/失效条件

若正式验证中 distinct-session 化后 EV 过于稀疏，无法驱动 persistence 通道（例如升层样本或 D
不足），说明 LoCoMo 的 session 边界不足以作为本操作化的独立验证代理。按结局 (c) 报告欠功效，
不得恢复同 session 重复投票来追求结果。

### 被拒绝方案

维持“后续 session 内每次 duplicate 均计 EV”。拒绝理由：同一 session 内没有跨过协议 §3 所定义
的去相关事件，让单一来源重复投票与原则 B 的独立性代理不一致。

## 4. B3 — CORE 纳入召回与关系分类

### 裁决

CORE 记忆加入 top-1 召回候选集。长期记忆的稳定性来自高写入/修改门槛，而不是对后续输入隐身。

候选选择规则：

1. 在 WORKING、CONSOLIDATED、CORE 全部候选中取余弦最高者；
2. 相似度完全相同时，层级顺序为 `CORE > CONSOLIDATED > WORKING`；
3. 同层仍相同时，使用稳定的内容键与 ID 兜底，禁止依赖容器遍历顺序。

同分 CORE 优先是 PI 补充裁决，不是实现细节：它阻止已经沉淀的同一事实再次走完整条晋升路径。

### CORE 命中后的四关系处置

| 关系 | 处置 |
|---|---|
| duplicate | 不写新记忆；满足 B1 时 CORE `EV +1`。该计数只供审计，不驱动 v0.2 决策。 |
| related | CORE `IA +1`；新事实正常写入 WORKING。该 IA 只供审计。 |
| mergeable | 不写新记忆；CORE `local_reorganization_trigger +1`；日志保存**完整增量文本**及来源，作为 v0.3 合并执行债的原料。 |
| contradict | 新断言写入 WORKING；与 CORE 建双向 conflict link；CORE `conflict_trigger +1`；不降级、不删除、不裁决。 |

CORE 永不进入 v0.2 的晋升、淘汰或降级路径。CORE 的 EV/IA/trigger/conflict 在本版都是描述性计数，
不得“顺手”接入任何决策。

### 已知边界

- mergeable 的结构性增量在 v0.2 只被识别和完整留痕，不执行合并；
- CORE 被后续输入矛盾时只标记，不裁决、不解封、不降级；
- 合并执行、矛盾裁决与“低变化率但能吸收真增量”的 CORE 更新机制属于 v0.3。

### 改变的可观测量

- WORKING 写入量预期下降；
- 重复晋升路径被切断，升层总数及 D 可能下降；
- CORE 会出现新的 EV/IA/trigger/conflict 审计计数；
- normalized exact CORE 重复率作为**报告指标**，不作为测试失败断言；测试只守护确定性 exact duplicate
  路径不再新建副本。

### 反驳/失效条件

若 CORE 纳入后 `|D| < 20`，说明旧分歧可能部分来自重复晋升伪影。这属于测量净化后的欠功效结果，
触发预登记结局 (c)，不得撤回 CORE 召回来恢复样本量。

### 被拒绝方案

CORE 不纳入、只在事后报告重复率。拒绝理由：未被比对不等于经受住比对；隔离制造的是假稳定，
且已经产生相同事实多次晋升 CORE 的实际伪影。

## 5. B4 — P/F 比较单位是完整选择制度

### 裁决

协议采用以下固定表述：

> P/F 是两套完整的记忆选择制度，差异起点为存续/频率计分，经由晋升门槛、超容量淘汰、及由此
> 改变的后续召回集合传播。本实验比较制度整体的沉淀质量，不宣称隔离了计分函数的单因子效应。
> 单因子消融为后续版本方向。

C2 在 v4 中检验的是两套操作化制度的整体比较。理论层只保留 External Selection 与 Internal
Selection 的稳定区分，不冻结本轮实验的具体比较器；“唯一变更 = Migration Rule”等实验设计措辞
移入协议层。

### 改变的可观测量

不改变运行数据，但改变因果解释上限：D 不能被表述为“计分函数单因子效应”。

### 反驳条件

沿用 v4 §0：若 `|D| ≥ 20` 且 persistence 独有升层记忆的 reference-grounded evidence 命中率
不高于 frequency 独有升层记忆，则 C2 的 v4 完整制度操作化不获支持。

### 被拒绝方案

继续宣称只改变单一 Migration Rule。拒绝理由：策略已经同时控制晋升与超容量淘汰，并通过召回
集合产生路径依赖；该措辞会把制度比较伪装成单因子消融。

## 6. B5 — 不设置 EV=0 晋升禁令

### 裁决

保留：

`persistence_score = EV × 1.0 + IA × (1/e)`

只要求 C3 的权重方向性 `EV > IA`，不增加 `EV > 0` 硬门槛。纯 IA 记忆在累积足够信号后仍可能
由 persistence 制度晋升。

### 具体理由

预登记推测 2 要检查 `F\P` 是否富集 EV=0 记忆及其 evidence 命中率。若在 persistence 制度中
加入 EV=0 硬阻断，EV=0 不能晋升将成为定义上的必然，机制签名退化为人为门槛的同义反复；
允许 EV=0 在两种制度下均有晋升可能，才能保留具有信息量的对照。

### 改变的可观测量

无；这是对既有公式的保留裁决。

### 反驳条件

若正式结果显示 persistence 独有或重叠升层中的 EV=0 记忆同样系统性缺乏 reference-grounded
evidence，C3 的当前权重与阈值操作化应在后续版本重新审视，但不得回改本轮规则。

### 被拒绝方案

`EV=0` 一票否决。拒绝理由：它把“外部权重更高”改写成“外部信号是必要条件”，超出 C3，且会杀死
推测 2 的非平凡机制对照。

## 7. B6 — reference-grounded evidence 评估契约

### 裁决

正式 judge 的每次输入必须同时包含：

- 被评估记忆 `memory`；
- 探针问题 `question`；
- LoCoMo 标准事实/答案 `reference_fact`。

判定问题是“该记忆是否包含支持 reference fact、从而正确回答 question 所需的事实”，不是只判断
话题相关性或表面可答性。

### 标签、计分与失败处理

- `包含 = 1.0`
- `部分 = 0.5`（本轮固定，不再作为 §8 待校准自由度）
- `不包含 = 0.0`
- 标签必须互斥解析，`不包含` 不得因包含子串“包含”而命中；
- probe 缺失 `reference_fact` 时不得进入正式评估；
- judge 调用失败的 `(memory, probe)` 对从有效判断分母剔除并单独计数；
- 某记忆全部 probe 均无有效判断时标记 `unscored`，不伪装为不命中；
- `judge_failure_rate = 失败调用对 / 全部计划调用对`；
- `judge_failure_rate > 5%` 时整次评估标记无效并以非零状态退出；
- 正式评估不得在缺少真实评判端配置时静默降级为 mock。

### 改变的可观测量

evidence hit rate 从“对问题的表面可答性”收紧为“相对于标准事实的证据命中”；有效分母、失败率与
未评分记忆数成为必须报告的观测量。

### 反驳/失效条件

- 失败率超过 5%：仪器失效，本次评估不产生 C2 证据；
- 人工 50 条锚点与主裁判一致率未达到冻结标准：评判端方案不得进入正式运行；
- 有效评估完成而 `h_P ≤ h_F`：C2 的 v4 操作化不获支持。

### 被拒绝方案

- 不提供 reference fact：拒绝，因为测到的是可答性而非正确证据；
- 将 judge 失败折算为 0：拒绝，因为它会惩罚更容易触发评判端基础设施/解析失败的一侧制度。

## 8. B7 — 关系分类解析失败采用硬失败

### 裁决

关系分类只接受协议定义的合法标签及明确列出的同义 token：

1. 未知、空或不可解析响应不缓存；
2. 保持 3 次重试；
3. 每次失败记录 `classification_unparsed` 审计信息；
4. 重试耗尽后本轮硬失败，不降级为 `unrelated`；
5. A3 轮级原子性必须先落地：失败时回滚本轮全部状态与状态事件；
6. 回滚完成后保留 `classification_unparsed` 与 `turn_failed` 失败审计事件；
7. runner 非零退出，不在污染状态上继续后续轮次；
8. 恢复方式为保留合法 LLM 缓存、清理运行状态后从第 1 轮确定性重放。

### 改变的可观测量

解析失败不再转化为新 WORKING 记忆；正式运行可能中断；新增失败次数、失败轮次与恢复次数。

### 反驳/失效条件

若在完成重试与 I/O 韧性措施后，正式冒烟仍频繁触发硬失败，导致运行不可完成，应把分类器可靠性
判为未达冻结条件，而不是恢复静默 unrelated 降级。

### 被拒绝方案

重试后降级为 unrelated 并继续。拒绝理由：它会把基础设施/格式故障变成真实动力学事件，改变写入
和后续召回集合，且无法从最终状态识别污染来源。

### PI 裁决与边界

PI 选择**路径 A（小额付费、保持仪器简单）**。冻结前先在已暴露的 `conv-26` 上运行 50–100 轮
真实 API 校准，以请求级实测用量换算全量成本；在此之前不得运行真实 API。本工程批次明确不加入：

- 批量/多项合并提取；
- 本地 NLI 分类器或 LLM/NLI 双仪器；
- RPD 账本、真正的中途检查点或其它“零成本路线”基础设施；
- 任何正式验证集选择、正式评估或预登记结论。

关系分类仪器据此固定为现有的 **LLM 五选一**。50 对人工标注仍用于检验该仪器是否可靠，
不再用于在 LLM 与本地 NLI 之间事后挑选。`conv-26` 继续只属探索集，其余验证候选不得因本次
成本校准而被接触。

### 确定性 exact duplicate 规则

在三层 top-1 召回已经选定受体、且候选已通过 `R_RECALL` 后，若新记忆与受体在协议唯一
归一化函数（小写、去标点、折叠空白）下均非空且完全相等，则直接判为 `duplicate`：

- 不调用关系分类 LLM，也不读取或写入 pair cache；
- 对 P/F 两种制度完全对称；
- 后续 EV、`total_activation` 与去重仍严格走 B1/§2.3，规则只替代关系标签的来源；
- 必须记录 `rule_based_duplicate`，并在去重事件中记录
  `classification_source=normalized_exact_rule`；未命中该规则时记为 `classifier`。

**改变的可观测量**：精确重复对的分类 API 请求数降为零；相同 `(new, existing)` 对在 P/F 中的
标签不再受模型采样影响；若模型此前会误分 exact pair，则 EV、激活计数、写入量与 D 也会相应改变。

**失效条件**：若审计发现上述归一化会把语义不同的文本折叠为同一键，或 exact 规则在两制度中
未对称执行，则相关运行无效；必须新增协议修订，不得通过扩大模糊匹配、相似度阈值或语义短路来
“顺手修复”。本裁决只覆盖归一化后的逐字相等，不授权低相似度 `unrelated` 短路变更。

### 既有裁决的实现收紧（不新增理论自由度）

- B6 的“部分”分固定为代码常量 `0.5`，删除环境变量覆盖；judge 输出上限为 6 tokens。
- 关系分类输出上限为 6 tokens；B7 的三次重试只处理**可解析性失败**。429 仍由 HTTP 层退避，
  其它传输、鉴权、配置或计量错误保留原异常身份并立即触发轮级回滚，不伪装成
  `classification_unparsed`。
- 正式 judge 必须在调用前解析驱动端与评判端模型家族；未知家族或同家族一律 fail closed。
- 每次真实 HTTP 尝试均记录角色、模型、操作、逻辑调用 ID、尝试序号、状态、耗时、输入/输出
  字符数及服务商返回的 token usage；关闭 SDK 隐式重试，429 只经显式退避并按真实请求逐次计数。
  缓存 hit/miss 由同次运行的
  两级缓存统计单独报告，并与 API 汇总共同持久化为 `run_metrics` 事件；不把零请求的 cache hit
  冒充 HTTP 请求。
- `preflight` 是只读预检：可精确计算提取 cache miss 与提示字符量；关系分类次数依赖状态演化，
  必须明确报告为未知，不能给出伪精确值。
- 受保护运行禁止 `--no-cache` / `--refresh-cache`，要求真实模型、显式 P/F 策略、temperature=0、
  已配置密钥，并以独占锁强制共享缓存的 P/F 串行运行。硬杀进程遗留锁不得自动删除，须人工核验。
- 事件、请求计量与评估文件名使用同一运行 tag 派生，避免跨运行错配。
