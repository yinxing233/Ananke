# 治理案卷：三个可审计的漂移事件

> 本文件是求职作品的**治理展品**：记录本项目如何让不可靠的 AI 执行者产出可审计的受控实验。
> 每个 case 回答三个问题：**发生了什么 / 怎么被抓住的 / 制度怎么改的**。
> 所有事实均可在 `docs/` 与 `logs/` 的日志、SHA256 指纹、DECISIONS 条目中复核。

---

## Case ① — 协议对照审查：实现阶段的"顺手修复"如何被逐项拦下

**发生了什么**

协议 v4 的 B1–B7 裁决集冻结后，实现按 A3 → A1/B6 → A2/B7 → A4/A5/B2 → B1 → B3 顺序以
"Red → Green"切片落地。在最后一个阶段（阶段 7），实现执行者做了**逐条协议对照审查**，
发现三类"实现与协议条款不一致"的缺口：日志部分落盘的回滚边缘、三层文件准备失败时的原文件
保护、`unscored` 记忆在升层集合与命中率分母中的归属、非法缓存/自定义分类标签的 fail-closed。

**怎么被抓住的**

不是靠"相信执行者自报完成"，而是靠**逐条对照协议原文**——每一类缺口都先补失败测试
（Red），再最小实现（Green），独立提交（`0699745`）。最终确定性验收 `70 passed` + 红线核对
（未改 persistence 公式/阈值、未改 CORE 晋升规则、未改 P/F 制度定义、未跑正式语料）。

**制度怎么改的**

- 每一轮实现都必须走"Red → Green → 独立提交 → 红线核对"的闭环；
- 协议对照审查成为实现阶段的固定环节，不只依赖测试通过；
- 同类漂移在工具层也立了纪律：2026-08-08 `dev_simulate.py` 演示链静默断裂（exact-dup 短路
  使 script 队列错位、关键事件缺失、且无测试守护）被一致性审查发现后，立下**守护断言纪律**：
  任何声称覆盖事件 X 的工具必须自带可运行断言，缺失即非零退出；工具 docstring 的能力声明 =
  其断言集的最小上界；协议条款变更后必须扫描所有声称覆盖该条款的工具。

## Case ② — XLSX 销毁事件：审计链断裂，以及一次被否决的"禁令"

**发生了什么**

标注过程产生的中间文件（人工标注 XLSX）在"内容迁移到 `cases.jsonl`"后被删除，只留下
SHA256 记录。审查者指出：**哈希只能验证"文件是否被改动"，无法验证一个已不存在的文件**——
审计链在第三方核验之前就断了。

**怎么被抓住的**

外部审查（Claude）核对迁移记录时发现"核验者是执行迁移的 agent 自己，且它在任何第三方核验
之前销毁了对照物"。严重度评估：损害有限（12 个边界案例反正要重裁），但**模式**危险——执行者
在验收语义上自行裁量。

**制度怎么改的**

第一反应是立"删除权禁令"（agent 无删除权，删除是 PI 专属动作）。但 PI 用**奥卡姆剃刀**否决了
这条禁令：现代 agent 在未授权时不会乱删，且 **git 可回退已构成足够兜底**——"知道什么时候不加
规则"比"加了规则"更能证明治理判断力。最终制度改动是**最小化的两条**：删除前确认内容已在别处
（git 跟踪或接管文件），删除走 git 可回退。被否决的禁令本身也留档，作为"制度冲动被克制"的证据。

## Case ③ — 输入闭包裁决：一条规则推翻人机共识，代价被显式登记

**发生了什么**

50 对人工标注与分类器一致率仅 40%。深挖发现：分类器运行时只收到两条记忆文本（两句话），
而人工标注者（PI）可能带着 LoCoMo 原对话的上下文判断——**校准对象是接口，接口收到的就是
两句话**。据此立"判断输入闭包"规则：判定关系时只使用分类器实际收到的两条文本，不回看原对话
补入共指、因果或事件身份。

**怎么被抓住的**

案例 P002 是干净的证明：已发生的露营 vs 考虑中的露营计划，人工和模型都判 mergeable（人都
自然脑补"计划实现了"），但闭包规则裁定 related——**规则推翻了人机共识**。这不是谁标错了，
是"对错"的定义域被换了。

**制度怎么改的**

- 输入闭包作为**协议级裁决**入 DECISIONS §12（追认记录 2026-08-11），不是 agent 的 README 草稿；
- 代价被显式登记：闭包使无法确认同一性的案例统一降档到 related（"related 汇"效应）——related
  的动力学后果是写新记忆 + IA+1，记忆库更碎、激活更弥散，作为**已登记仪器属性**写入冻结文档；
- 12 个边界案例由 PI 逐例裁决（最终 3 mergeable / 7 related / 2 unrelated / 0 duplicate /
  0 contradict），两条显式规则（模态一致性、同谓词）入操作定义；
- 归因修正：PI 标注时未看 LoCoMo 对话（天然闭卷），κ 低主因是两句话欠定 + 指南未定稿，
  而非"标注者上下文泄漏"。

## 附：这些事件为什么值得信任

1. **每一件都有可复核痕迹**：commit SHA（`0699745` / `a969e5b`）、事件日志
   （`logs/conv26_events.jsonl` 949 条）、指纹清单（`FREEZE_MANIFEST_v0.2.json`）、
   运行回执（`IGNITION_RECEIPT_v0.2.md`，10 产物 SHA-256 与备份逐文件相等）；
2. **审查是跨 agent 的**：GLM 三轮证伪、Claude 协议对照、GPT 独立复核、PI 抽查锚点——
   不是单一执行者自报成功；
3. **失败被如实记录**：EV=0（外部验证 0 激活）、duplicate 分类器盲区、两项推测
   `not_testable`——报告的结论边界与案卷的治理故事共享同一份诚实。
