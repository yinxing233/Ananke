## 0. 一页速览

- 项目 = 约束场理论的**实验仪器**，唯一检验对象 = 工程推论 **C2**（存续检验驱动的跨层迁移优于访问频率驱动）。
- 架构 = 三层记忆（WORKING / CONSOLIDATED / CORE）+ 两道迁移闸 + **v4 召回-分类两段式**（取代 v3 余弦阈值判定）。
- 主测量 = 分歧集 D = (P∖F) ∪ (F∖P) 上两侧独有升层记忆的 **judge 端 evidence 命中率**（P=persistence 升层集，F=frequency 升层集）。
- 关键文件：`pipeline.py`（编排）· `relation.py`（关系分类器）· `migration.py`（两闸+淘汰）· `cache.py`（两级缓存+形式运行锁）· `divergence_analysis.py`（主测量消费端）· `evaluate.py`（独立评判端）。
- 测试：11 个测试文件，守护 A1–A5 / B1–B7 裁决与 v4 语义（`test_scenarios.py` 20 个 v4 场景测试 + 各裁决守护测试）。

## 2. 单轮数据流（pipeline.process 完整路径）

```
user_input (+ session_id / dia_id / speaker / session_datetime)
  │ ① 事件日志 context 挂接轮次来源元数据
  │ ② MemoryStore.snapshot() + 双重事务（logger + store）→ 失败全回滚
  ▼
extract_memories()                        ← 提取（LLM，temperature=0）
  │   缓存键 = normalize(speaker|datetime|input)（跨人物/日期隔离）
  ▼
对每条提取记忆 m：
  _recall()：余弦召回 cos≥R_RECALL 的 top-1 受体 e
  │   三层都参与（B3）；同分裁决 CORE>CONSOLIDATED>WORKING，再按 (content,id) 兜底
  ├─ 无候选 → 视为 unrelated 直接写入 WORKING
  ├─ normalize(m) == normalize(e) → 确定性 duplicate（短路，不调分类器，2026-08-08 修订）
  └─ 否则 → relation_classifier.classify(m, e) 五分类（LLM，max_tokens=6，B7 三尝试）
       │   pairs 缓存命中 → 直接返回；miss → 调用 → 合法标签才落缓存
       ▼
_handle_relation() 信号映射（受体语义，全部计到既有记忆 e 上）：
  duplicate   → 跨 session 且非 guided：total_activation+1、EV+1（每 session 至多一次，B1）；不写 m
  contradict  → e.conflict_trigger+1、total_activation+1；写 m + 双向 conflict_links（漂移2）
  mergeable   → e.local_reorganization_trigger+1、total_activation+1；不写 m（语义债，防信号泵）
  related     → e.internal_activation+1、total_activation+1；写 m
  unrelated   → 写 m（无信号）
  ▼
enforce_working_capacity()               ← 淘汰跟随策略 score（#13 修复），平票按 (score, content, id)
promote_working_memories()               ← 第一道闸（P/F 各自计分 vs 阈值 3.0）【分歧集 D 在此测量】
promote_consolidated_memories()          ← 第二道闸：merge_trigger≥2 且 conflict_trigger==0（阻断器，与策略无关）
```

## 6. ⚠️ 通读代码时发现、Claude 审查预登记前必须知道的三件事

> 本节是 2026-08-13 点火前的诊断快照，用于证明空集风险在看到全量结果前已被识别。
> “P⊆F 恒成立”与“推测 2 已可测”均需按 §9 收窄，不再作当前结论。

### 6.1（最重要）P⊆F 数学事实 → 推测 1 在代码中"空洞成立"

**推导**（`models.py` 公式 + `promotion.py` 共用阈值 3.0）：
```
persistence_score = EV + IA×(1/e)  ≤  EV + IA = frequency_score   （恒成立，IA≥0）
```
故**计分层面 P ⊆ F，P∖F ≡ ∅**。P 独有升层集在数学上不存在。

**代码证据**：`divergence_analysis.py:139`
```python
"conjecture1_held": (not (only_P and only_F)) or (h_only_P > h_only_F),
```
当 `only_P`（P∖F）为空时——按上述推导**恒为空**——`conjecture1_held` 直接为 True。即：**推测 1 会被代码判定为"成立"，但这个成立是空洞的（空集上的成立），不可测也不可反驳**。程序注释"仅当两侧独有集均非空时才有意义"实际上回避了"P∖F 恒空"这一数学事实。

**对预登记的影响**（Claude 审查时重点）：
- 主推测 1 的表述（"persistence 独有升层命中率 > frequency 独有升层"）**不可测**，须降级为"制度整体的次级效应"（唯一来源 = 容量淘汰/记忆库分叉的间接路径），或将主测量改写为单边形式。
- **真正可测且锋利的是推测 2**：F∖P（frequency 多升、缺外部验证的记忆）是否富集 EV=0 且 judge 命中率更低（`divergence_analysis.py:118-123` 已正确实现，EV 仅作分段被解释项）。
- 在 PI 拍板修订 RESEARCH_CONJECTURES 之前，**不要**带着现行推测 1 冻结 PREREGISTRATION。
- 补充：若未来想让 P∖F 非空（恢复双边比较），唯一途径是非对称阈值（P 阈值 < F 阈值），但那会把"阈值差 + 来源加权"混进差异，违背"唯一变量"原则（GLM R1 教训），不推荐。**正确方向是接受单边检验。**

### 6.2 `activation.py` 是 v3 遗留，勿接入

`detect_activations` 不再被 v4 管线调用（信号由 `pipeline._handle_relation` 直接登记）。`02_IMPLEMENTATION.md:106` 已标注"勿再接入"。Claude 若看到该模块被误接，应判定为漂移。

### 6.3 两个已登记的失效模式，审查时留意

- **top-1 召回的方向性偏向**（`pipeline.py` 注释 + 协议 §2.2）：矛盾对（改一个词）余弦往往高于复述对（换个说法），top-1 会系统性偏向捕获 contradict 而漏掉 duplicate→EV——在含改口的语料上是对 persistence 的**单向压制**（漏 EV = 低估 persistence）。冒烟时须观察实际候选分布，不得静默切 top-k。
- **缓存 key 解析陷阱**（`export_annotation_pairs.py` 头部）：model_tag 含 `|`，两段记忆用 `||` 分隔，必须 `rpartition("||")` + `rsplit("|", 2)`，不能整体 `split("|")`。

## 7. 已知债（v0.3+，均已登记）

1. mergeable 不写新记忆（合并执行留 v0.3+）。
2. conflict 阻断器无裁决/解封机制：conflict_trigger>0 一次触发即**永久阻断**，自然语料 contradict 高频时 core 晋升率可能趋零（阻断率≥30% 预警线已实现，冻结前须重评阻断条件）。
3. 归一化不处理改写容忍度：措辞不同但同事实的两条记忆仍判为两条分歧（假阳性）。
4. 上下文感知分类（是否改变 C2 结论）为 v0.3 合法后续实验，冻结前禁入。
5. 单因子消融（score 函数 vs 阈值分离）为后续版本方向——但 §6.1 表明计分层差异本身就是单因子（仅 IA 折扣），这是利好消息。

## 9. 2026-08-18 点火后校正

### 9.1 空集缺陷被现实数据激活，已修正

归一化第一闸集合实测为 P=14、F=62、交集=14、P-only=0、F-only=48、D=48。原代码
`(not (only_P and only_F)) or ...` 会把推测 1 的空集直接判为 True；该缺陷已修为三态：
`held / not_held / not_testable`。任一独有集为空或没有有效 judge 分数时，推测 1 为
`not_testable`；`F∖P` 内 EV=0/EV>0 任一子组为空或没有有效分数时，推测 2 亦为
`not_testable`。对应回归测试已加入 `tests/test_evaluate.py`。

### 9.2 `P⊆F` 只能在明确层级上陈述

对同一记忆的同一状态快照，Frequency 的 `total_activation` 包含 Persistence 所用的 IA，也包含
mergeable/contradict 等非 EV 关系事件；两者门槛均为 3 时，Persistence 的 IA 还要乘 `1/e`。
因此快照计分关系强烈预期 P 升层者也会满足 F。但 P/F 是两次独立动态运行，晋升、淘汰、召回与
写入可以让状态路径分叉；故“全局升层集永远 P⊆F”不是已证定理。可防御的说法是：
本次运行经归一化后观察到严格嵌套 `P⊂F`，与计分层的包含方向一致。

### 9.3 EV=0 使两项推测同时失去识别力

两侧终态记忆的 EV 总和均为 0。Persistence 在本次运行中只由 IA/e 累积，Frequency 由更宽的
`total_activation` 累积；因而两制度有真实操作分叉，但区分 External Selection 的变量没有激活。
推测 1 缺 `P∖F`，推测 2 缺 `EV>0` 子组，故两者均为 `not_testable`。点火前对
“推测 2 真正可测”的判断已被数据否定。

EV=0 保留两种并存解释：duplicate 分类器盲区（开发集 5 例命中 0），或 `conv-26` 在当前
提取表示下真实缺少跨 session duplicate。现有数据无法区分，应作为 v0.3 的仪器修复问题，
不能改写为 C2 的支持证据。

### 9.4 阻断风险的本轮结果

`core_promotion_blocked` P=181/F=384 是重复审计事件，对应的唯一被阻断记忆只有 P=1/F=2；
真实 `conflict_link` 为 P=5/F=4。CORE 最终为 P=6/F=17，所以“自然语料下 CORE 趋零”未在
本次 `conv-26` 运行中实现；这是一次运行结果，不是对其它语料的结构性保证。
