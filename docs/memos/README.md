# docs/memos/ — 备忘录（决策备忘 / 协作约定 / 临时指引）

> **用途**：存放**短生命周期的操作类备忘**——需要 PI 拍板的决策备忘、PI↔agent 协作约定、
> 执行前需要扫一眼的指引。与 `archive/`（历史文档归档）和 `docs/` 根下权威文档（00–03 + 裁决）
> 的关键区别见下表。
>
> **为什么存在**：实验仪器正确运转的前提是 PI 只在**决策点**起作用，而非全量阅读每个文件。
> 本目录就是"决策上浮、信息下沉"的落点：agent 把需要拍板的东西收敛成这里的一页纸，
> PI 花几分钟看完即可决策，不必追着每个产出跑。

## 与相邻目录的分工

| 目录 | 性质 | 生命周期 | 例子 |
|---|---|---|---|
| `docs/` 根下 00–03、DECISIONS | 权威知识（理论/协议/实现/日志/裁决） | 月–年级 | `01_PROTOCOL_v4.md` |
| `docs/archive/` | 已被取代的历史文档 | 永久保留供审计 | `01_PROTOCOL_v1.md` |
| **`docs/memos/`** | 操作类备忘（待决策/协作约定/临时指引） | 天–周级，决策完即闭 | `2026-08-08_calibration_decision_memo.md` |

## 纪律

1. **一个 memo 只装一个主题**（一次只聊一个东西——与用户阻力系统一致）。
2. **决策备忘必须在标题/头部写明"决策点"**：PI 只需回答"选 A / B / C"或"我改主意了"。
3. **memo 不是协议**：memo 可以提议改协议，但改协议本身必须走 `01_PROTOCOL_vN.md` 的升版流程；
   memo 只是决策前的准备工作，不是决策本身。
4. **决策完成后**：memo 头部标注"已决策 → 指向落地文件"，移入 `archive/` 或保留标注；
   不留"悬空决策"（开而未完的决策是协作噪声）。
5. **不重复造轮子**：已在 00–03 / DECISIONS / 研究日志写过的内容，memo 只引用不复制。

## 文档生命周期纪律（2026-08-08 立，防文档膨胀）

> 背景：文档不是越多越麻烦——麻烦的是**没有过期时间的文档**和**所有人默认读全部**。
> 文档体系（00→03→archive→memos）本身就是防膨胀结构，前提是每份文档都有明确的
> "过期触发点"和"归档条件"。以下是两条机制：

### 机制一：临时文档必须声明"过期触发点"

| 文档 | 过期触发点 | 过期后去向 |
|---|---|---|
| `CALIBRATION_PATH_A.md` | 100 轮校准完成那一刻 | → `archive/` |
| `docs/memos/*`（决策备忘） | 决策拍板那一刻 | 内容沉淀进 DECISIONS / 研究日志，memo → `archive/` |
| `RESEARCH_CONJECTURES.md` | 协议冻结、`PREREGISTRATION.md` 创建时 | 保留为来源文档（v4 §7 已声明，不得删改升格） |
| `docs/archive/` 内文件 | 永久保留 | 不清理（演进轨迹，供审计） |

**体检惯例**：每次协议冻结 / 版本发布时，全量扫一遍 `docs/`，把到期的移入 `archive/`、
把重复的合并、把悬空 memo 关闭。体检本身不新增文档，只做"回收"。

### 机制二：按角色给"必读清单"，不默认读全部

> 文档的价值在"该读的人找到该读的"，不在"所有人都读完"。读全部 = 又把全量平铺的
> 问题搬回文档层。

| 角色 | 必读 | 按需 |
|---|---|---|
| **PI（人类）** | `docs/memos/`（待决策一页纸）、会话开头的状态摘要 | 协议决策时读 00/01 全文 |
| **实现类 agent** | `02_IMPLEMENTATION.md` + `DECISIONS_v0.2_freeze.md` + 当前协议（v4） | 理论背景读 00 |
| **协议决策类 agent** | `00_THEORY.md` + 当前协议 + DECISIONS + RESEARCH_CONJECTURES | 历史脉络读 03 |
| **审查类 agent** | 全量（一次性审计场景） | — |

agent 交接 brief 必须包含：当前 `docs/memos/` 索引 + 本角色必读清单，
否则新 agent 回到"全量平铺"默认行为。
