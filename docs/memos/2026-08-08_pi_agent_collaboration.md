# 协作约定 · PI ↔ agent（决策上浮 / 信息下沉）

- 日期：2026-08-08（PI 认可："未来人类肯定跟不上大模型的产出速度，人类需要在关键的地方起作用，而不是全量阅读每一个文件每一条代码"）
- 状态：**已生效**（本项目所有 agent 会话的协作默认值）
- 适用范围：Ananke 项目内所有 agent 会话（本约定应随 agent 交接 brief 一起传给新会话）

---

## 0. 一句话

**人类是 CORE（慢层），agent 是 WORKING（快层）。工作层可以高速运转，但每次跨层接触必须经过
决策闸门——高频扰动不得淹没慢层。** 这正是 Ananke 自身理论（沉淀速率分离 + 单向阀）在协作
结构上的镜像。

## 1. 核心原则

- **决策上浮（decision up）**：只有需要 PI 拍板的内容才上报；信息进文档/归档。
- **信息下沉（information down）**：agent 的产出默认是"信息"（进文档/日志/记忆），
  只有明确标注"决策"的才进 PI 的 inbox。
- **PI 的职能 = 决策点把关，不是全量审阅**：PI 不需要读每一行代码、每一份报告；
  只需要在"协议该不该改、阈值该不该定、验证集该不该锁、预算该不该花"这些点上做决定。

## 2. agent 行为默认值（本约定生效后）

| # | 规则 | 说明 |
|---|---|---|
| 1 | **一次一个切片** | 每轮只推进一个窄范围任务，做完停下，不连续推进多个任务 |
| 2 | **一页纸摘要** | 每次交付附：做了什么 / 验证了什么（命令+结果）/ 需要 PI 决策什么（若无则明说"无需操作"） |
| 3 | **决策给选项 + 推荐** | 需要拍板时给 A/B/C + 推荐项 + 理由，PI 做选择题，不做填空题 |
| 4 | **只有分歧才上报** | agent 自报进度不算上报；出现分歧/漂移/需选择时才打扰 PI |
| 5 | **会话开始先读记忆** | 先读 `.workbuddy/memory/` + `docs/memos/`，30 秒恢复上下文，再给"当前状态 + 待决策清单" |
| 6 | **决策收敛成清单** | 不逐条打扰；攒成决策队列批量给 PI（一次看清单，而非被多次打断） |
| 7 | **可随时叫停** | PI 说"只报告不推进"即停在一个安全停点（对应 A3 轮级原子性：不留半成品状态） |

## 3. 与现有项目纪律的关系

- **不冲突**：本约定是协作层的"通信协议"，不改协议 v4 的任何操作定义；
  所有理论/协议/实现内容仍以 docs/ 权威文档为准。
- **互补**：`docs/memos/` 是"决策上浮"的落点（agent 把待决策项写成 memo）；
  守护断言纪律（`03_RESEARCH_LOG.md` 2026-08-08 条目）是"信息下沉"的质量保障。
- **交接**：换 agent 会话时，交接 brief 必须包含本约定 + 当前 `docs/memos/` 索引，
  否则新 agent 回到"全量平铺"默认行为。

## 4. PI 的回报（为什么值得）

- 决策质量上升：PI 只在关键点用力，每个决策都有选项+推荐+理由，而非被淹没后仓促拍板。
- 静默期缩短：agent 的产出有守护断言 + 一页纸摘要，漂移当轮暴露，不再等审计才发现
  （对照：dev_simulate 演示链断裂静默了近一天）。
- 可证伪性保住：PI 的注意力回到理论/协议层，实验的"人"部分（设计、裁决、预登记）
  不被"工程噪音"稀释——这正是仪器能持续产生干净 Evidence 的前提。
